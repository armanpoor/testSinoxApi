## ۱. این پروژه اصلاً چه کاری می‌کند؟

وقتی شما اشتراک **Google AI Pro** می‌خرید، گوگل به شما دسترسی مدل‌های قوی مثل Gemini 4 را از دو راه می‌دهد:

- **راه اول (رسمی):** یک API Key از سایت [Google AI Studio](https://aistudio.google.com) بگیرید و با آن برنامه بنویسید. این راه ساده است اما سهمیه آن با اشتراک Pro وب **جداست** و برای مدل‌های خاص باید جداگانه پول بدهید.
- **راه دوم (همین پروژه):** همان اکانتی که در مرورگر با آن به `gemini.google.com` می‌روید و چت می‌کنید، را به یک **سرور API محلی** تبدیل کنیم. بعد هر برنامه‌ای که بلد است با API «OpenAI-compatible» یا «Anthropic» حرف بزند، می‌تواند از مدل‌های اشتراک شما استفاده کند — انگار که یک سرور ChatGPT شخصی روی کامپیوتر خودتان راه انداخته‌اید.

**یک تشبیه ساده:** فرض کنید یک باشگاه ورزشی اشتراک دارید اما فقط حضوری می‌توانید از آن استفاده کنید. این پروژه مثل این است که یک کارت‌خوان شخصی بسازید که ورود شما را به باشگاه «ترجمه» می‌کند تا دوستانتان (برنامه‌های شما) هم بتوانند از استخر و سالنه استفاده کنند. باشگاه هنوز همان است، فقط حالا از راه دور هم قابل استفاده است.

**چرا این کار به درد می‌خورد؟** چون ابزارهایی مثل Claude Code (دستیار کدنویسی ترمینالی) و Cline (افزونه VS Code) به یک API قوی نیاز دارند و اگر اشتراک Gemini Pro دارید، می‌توانید بدون هزینه اضافه، همین مدل‌ها را در این ابزارها به کار بگیرید.

## ۳. مفاهیم پایه برای کسی که فقط ChatGPT کار کرده

اگر تا به حال فقط با ChatGPT یا جمنای وب چت کرده‌اید، این بخش برای شماست. چند کلمه را ساده توضیح می‌دهم:

### API چیست؟
API یعنی «رابط برنامه‌نویسی». به زبان خیلی ساده: وقتی شما در سایت ChatGPT تایپ می‌کنید، یک انسان پشت صفحه نیست که جواب بدهد؛ یک برنامه است. API یعنی راهی که برنامه شما بتواند **بدون مرورگر و بدون کلیک**، مستقیم از مدل هوش مصنوعی سوال بپرسد و جواب بگیرد. مثل این است که به‌جای رفتن به صندوق فروشگاه، از در پشتی بار بگیرید.

### مدل چیست؟
مدل = موتور فکری. `gemini-4-hydrogen` و `gemini-4-carbon` اسم موتورهای فکری گوگل هستند. هر کدام سرعت و هوش متفاوتی دارند (بخش [۹](#۹-مدلها--hydrogenneoncarbon-و-داستان-argon) را ببینید).

### چت‌جی‌پی‌تی چطور به این‌ها وصل می‌شود؟
در دنیای API دو «فرمت» رایج وجود دارد که تقریباً همه از آن‌ها تبعیت می‌کنند:
- **فرمت OpenAI:** آدرس `/v1/chat/completions` — از همه جا پشتیبانی می‌شود.
- **فرمت Anthropic:** آدرس `/v1/messages` — فرمت رسمی شرکت سازنده Claude و چیزی که Claude Code استفاده می‌کند.

هر دو فرمت یک کار می‌کنند: شما پیام می‌فرستید، جواب می‌گیرید. تفاوت فقط در «قالب» پیام است — مثل تفاوت نامه با پست عادی و فکس.

### Streaming (استریم) چیست؟
وقتی در ChatGPT جواب را کلمه‌به‌کلمه می‌بینید که جلوی چشمتان تایپ می‌شود، این «استریم» است. در API هم همین است: جواب به‌صورت تکه‌تکه می‌آید تا کاربر منتظر نماند. پروژه ما این را کامل پشتیبانی می‌کند.

### Tool Calling (صدا زدن ابزار) چیست؟
وقتی Claude Code می‌خواهد یک فایل را بخواند یا دستور اجرا کند، به مدل می‌گوید «یک ابزار به اسم read_file دارم، اگر لازم شد صدایش کن». مدل به‌جای متن، یک «درخواست ابزار» برمی‌گرداند (مثلاً: ابزار read_file با پارامتر path=main.py). برنامه شما ابزار را اجرا می‌کند و نتیجه را دوباره به مدل می‌دهد. این چرخه پایه‌ی همه دستیارهای کدنویسی است.

### Cookie (کوکی) چیست و چرا مهم است؟
وقتی در گوگل لاگین می‌کنید، گوگل به مرورگر شما چند رشته متنی می‌دهد که «کوکی» نام دارد. هر بار که صفحه‌ای از گوگل باز می‌کنید، مرورگر این رشته‌ها را می‌فرستد تا گوگل بداند «این همان کاربر است». پروژه ما هم از همین کوکی‌ها استفاده می‌کند: یک بار لاگین می‌کنید، کوکی‌ها را برمی‌داریم، و سرور محلی ما با آن کوکی‌ها **خودش را به‌جای مرورگر شما جا می‌زند**.

### Proxy (پروکسی) چیست؟
پروکسی یعنی «واسطه». سرور محلی ما یک واسطه است: برنامه‌ها به او می‌گویند «این سوال را از هوش مصنوعی بپرس»، او هم با کوکی شما به گوگل می‌گوید و جواب را برمی‌گرداند. چون روی همان کامپیوتر شماست، به آن «پروکسی محلی» می‌گوییم.

## ۴. معماری — سه لایه و دلیل هر لایه

تصویر کلی:

```
┌──────────────────┐
│  Claude Code /   │   برنامه‌های شما
│  Cline / curl    │
└────────┬─────────┘
         │  (فرمت Anthropic /v1/messages یا OpenAI)
         ▼
┌─────────────────────────────┐
│  لایه ۳: پل ترجمه           │  CLIProxyAPI (پورت 8094)
│  فرمت Anthropic ↔ OpenAI   │
└────────┬────────────────────┘
         │  (فرمت OpenAI /v1/chat/completions)
         ▼
┌─────────────────────────────┐
│  لایه ۲: موتور وب          │  gemini-web2api-go (پورت 8093)
│  جعل اثرانگشت کروم + کوکی   │
│  صف، سهمیه، ضدبن           │
└────────┬────────────────────┘
         │  (پروتکل داخلی وب گوگل، با اثرانگشت TLS کروم)
         ▼
┌─────────────────────────────┐
│  سرورهای gemini.google.com │
└─────────────────────────────┘
```

### چرا لایه‌لایه؟ چرا یک برنامه واحد نیست؟

**لایه ۲ (موتور وب — gemini-web2api-go):** این هسته اصلی است. یک فایل اجرایی Go که کارهای سخت را انجام می‌دهد:
- وقتی برنامه شما می‌گوید «به مدل gemini-4-hydrogen بگو X»، این برنامه درخواست را به فرمتی تبدیل می‌کند که صفحه وب جمنای استفاده می‌کند (پروتکل داخلی گوگل به نام batchexecute / WebChannel).
- **مهم‌ترین نکته فنی:** گوگل امضای شبکه مرورگر کروم را می‌شناسد (به این امضا «اثرانگشت TLS» یا JA3/JA4 می‌گویند — مثل امضای دست، ولی برای ارتباط اینترنتی). اگر یک برنامه پایتونی معمولی به گوگل وصل شود، گوگل می‌فهمد «این مرورگر نیست!» و ممکن است کپچا بدهد یا بلاک کند. این برنامه خودش را دقیقاً مثل کروم نسخه ۱۴۶ نشان می‌دهد — تا سطح جزئیات فریم‌های HTTP/2.
- کوکی شما را نگه می‌دارد، خودش آن را تازه (refresh) می‌کند، و اگر چند اکانت داشته باشید بینشان می‌چرخد.

**لایه ۳ (پل ترجمه — CLIProxyAPI):** چون موتور وب فقط فرمت OpenAI را خروجی می‌دهد و Claude Code فقط فرمت Anthropic را می‌فهمد، این لایه مثل «مترجم همزمان» بین دو فرمت جابجا می‌شود. اگر فقط با Cline یا برنامه‌های فرمت-OpenAI کار کنید، اصلاً به این لایه نیاز ندارید.

**لایه ۱ (مرورگر — فقط موقع لاگین):** مرورگر فقط یک بار باز می‌شود تا شما لاگین کنید و کوکی‌ها گرفته شود. بعد از آن **دیگر هیچ مرورگری در کار نیست** — همه‌چیز بدون مرورگر کار می‌کند. این نکته مهمی است چون بعضی روش‌های قدیمی، مرورگر را همیشه باز نگه می‌داشتند که هم رم می‌خورد (۲۰۰ تا ۵۰۰ مگابایت!) و هم با چرخش کوکی تداخل می‌کرد.

### چرا با اکانت اصلی این کار را نکنیم؟

استفاده از وب جمنای با اسکریپت، طبق قوانین گوگل یک «ناحیه خاکستری» است. احتمال بن وجود دارد (بخش [۱۰](#۱۰-قوانین-ایمنی-ضدبن--بخوانید-قبل-از-استفاده-روزمره)). اگر اکانت اصلی‌تان (که ایمیل و درایو و عکس‌های خانوادگی‌تان به آن وصله) بن شود، فاجعه است. اکانت فرعی می‌سازید، اشتراک را روی آن می‌خرید، و اگر اتفاقی افتاد فقط همان می‌سوزد.

## ۵. نصب گام‌به‌گام از صفر

### گام ۱: مخزن را کپی (clone) کنید

```powershell
git clone https://github.com/armanpoor/gemini-web-bridge.git
cd gemini-web-bridge
```

(اگر git ندارید، از دکمه Code → Download ZIP در همین صفحه استفاده کنید و فایل را باز کنید.)

### گام ۲: سرور موتور وب را راه بیندازید

```powershell
powershell -ExecutionPolicy Bypass -File scripts/01-start-proxy.ps1
```

این اسکریپت اولین بار باینری را دانلود می‌کند (حدود ۱۸ مگابایت) و بعد سرور را روی پورت **8093** بالا می‌آورد. در خروجی، چیزی شبیه این می‌بینید:

```
gemini-web2api-go v4.31.0
  Listening:   http://0.0.0.0:8093
  API key:     sk-gemini-XX...XX
  Admin UI:    http://localhost:8093/admin
```

**کلید API را یادداشت کنید** — اولین بار کلید به‌صورت مخفی‌شده نمایش داده می‌شود؛ کلید کامل را از پنل ادمین (تب Settings) بردارید.

### گام ۳: به پنل ادمین وارد شوید

در مرورگر بروید به `http://localhost:8093/admin` و توکن ادمین را بزنید (همان `change-me-123` اگر عوضش نکرده باشید، یا مقدار `ADMIN_TOKEN` که خودتان ست کردید).

### گام ۴: کوکی اکانت را وارد کنید

ادامه در بخش بعدی — این مهم‌ترین مرحله است.

### گام ۵: پل Anthropic را راه بیندازید (فقط برای Claude Code)

در یک پنجره PowerShell جدید:

```powershell
$env:GW2API_KEY = "sk-gemini-...."   # همان کلید گام ۲
powershell -ExecutionPolicy Bypass -File scripts/02-start-bridge.ps1
```

این سرور دوم را روی پورت **8094** بالا می‌آورد که `/v1/messages` دارد.

## ۶. گرفتن کوکی — مهم‌ترین و حساس‌ترین مرحله

### روش پیشنهادی: مرورگر موقت + اسکریپت

**قانون طلایی:** فقط **یک** موجودیت حق دارد کوکی‌های یک اکانت را «بچرخاند» (rotate). اگر مرورگر باز و سرور همزمان کوکی را عوض کنند، نسخه‌هایشان همدیگر را باطل می‌کنند و سشن شما ظرف چند دقیقه می‌میرد. پس بعد از گرفتن کوکی، مرورگر را ببندید.

**مرحله ۱ — کروم را با پروفایل موقت و پورت دیباگ باز کنید:**

```powershell
& "C:\Program Files\Google\Chrome\Application\chrome.exe" --user-data-dir="$env:TEMP\gemini-login" --remote-debugging-port=9333 "https://gemini.google.com/app"
```

این یک کروم کاملاً جدا از کروم اصلی‌تان باز می‌کند (پروفایل، تاریخچه و افزونه‌های شما در آن نیست).

**مرحله ۲ — با اکانت فرعی Pro‌دار لاگین کنید** و صبر کنید صفحه چت جمنای کامل بالا بیاید.

**مرحله ۳ — در همان PowerShell (بدون بستن کروم) اجرا کنید:**

```powershell
python scripts/03-extract-cookies.py
```

خروجی: `✅ 9 کوکی ذخیره شد در cookie.txt`

**مرحله ۴ — مرورگر موقت را فوراً ببندید.**

**مرحله ۵ — محتوای `cookie.txt` را در پنل ادمین (`http://localhost:8093/admin` → تب Cookie Pool → Add) بچسبانید و ذخیره کنید.**

اگر همه‌چیز درست باشد، تب Models در پنل یا `/v1/models` حالا مدل‌های پریمیوم مثل `gemini-4-hydrogen` و `gemini-4-carbon` را هم نشان می‌دهد.

### ⚠️ هشدار DBSC: چرا کروم ممکن است بدرد نخورد

از نسخه‌های جدید کروم، گوگل قابلیتی به نام **Device Bound Session Credentials (DBSC)** دارد: کوکی‌های حساس (`__Secure-1PSIDTS`) به «دستگاه» قفل می‌شوند و بعد از خروج از مرورگر، تازه‌سازی‌شان از طرف یک برنامه غیرمرورگری با خطا روبه‌رو می‌شود. نتیجه: کوکی‌ای که از کروم می‌گیرید ممکن است نیم ساعت تا چند ساعت بعد بمیرد.

**راه‌حل مطمئن:** لاگین را در **فایرفاکس** انجام دهید و کوکی را از آنجا بردارید (افزونه‌های Cookie-Editor). فایرفاکس DBSC ندارد و کوکی‌اش هفته‌ها زنده می‌ماند. روش دوم: کروم را در حالت **Incognito کامل** باز کنید، لاگین کنید، فوراً کوکی را بگیرید و فوراً ببندید (که در تست ما همین کار کرد).

> **تجربه واقعی ما (۲۰ نوامبر ۲۰۲۶):** کوکی‌ای که از کروم گرفتیم بعد از حدود ۳۰ دقیقه مرد و همه درخواست‌ها به خطای «cookie expired» خورد. دوباره مرورگر را باز کردیم (سشن در خود مرورگر هنوز زنده بود)، کوکی تازه گرفتیم و همه‌چیز برگشت. **درس:** با کوکی کرومی مثل شیر تازه رفتار کنید — همان روز مصرفش کنید؛ و اگر خطای مرگ کوکی دیدید، اول همان مرورگر را دوباره باز کنید و کوکی تازه بگیرید، نه اینکه فکر کنید اکانت بسته شده. نشانه مرگ کوکی: خطای «no SNlM0e in page» یا جواب‌هایی که ناگهان مدل رایگان می‌دهند.

### چند اکانت (Cookie Pool چند-اکانته)

چرا چند اکانت؟ چون سهمیه ۵ ساعته مدل‌های سنگین (مثل Carbon) روی هر اکانت Pro خیلی سریع تمام می‌شود. با دو یا سه اکانت، پروکسی خودش بین‌شان می‌چرخد و عملاً سهمیه‌تان دو/سه برابر می‌شود.

**مدیریت کامل با یک اسکریپت** (`scripts/05-manage-accounts.py`):

```powershell
# افزودن اکانت از فایل کوکی
python scripts/05-manage-accounts.py add --label arman3 --cookie-file cookie-arman3.txt

# افزودن مستقیم با رشته کوکی
python scripts/05-manage-accounts.py add --label arman3 --cookie "SID=...; HSID=...; __Secure-1PSID=..."

# لیست همه اکانت‌ها با وضعیت سلامت (ok / dead / error)
python scripts/05-manage-accounts.py list

# تست اینکه لاگین هر اکانت هنوز معتبر است (بدون مصرف چت)
python scripts/05-manage-accounts.py check

# بیدار کردن دستی چرخش کوکی یک اکانت (keep-alive)
python scripts/05-manage-accounts.py rotate 2

# روشن/خاموش/حذف
python scripts/05-manage-accounts.py disable 2
python scripts/05-manage-accounts.py enable 2
python scripts/05-manage-accounts.py delete 2

# اگر کوکی از مرورگری گرفته شده که چند اکانت گوگل دارد:
# اکانت دوم در آن مرورگر = /u/1 → عدد 1
python scripts/05-manage-accounts.py authuser 2 1
```

(قبل از اجرا دو متغیر محیطی را ست کنید: `GW2API_ADMIN` آدرس پنل و `GW2API_ADMIN_TOKEN` توکن ادمین.)

**راه سریع‌تر — چند اکانت با یک مرورگر واحد** (`scripts/06-add-multi-accounts.ps1`): این اسکریپت یک کروم موقت باز می‌کند، شما اکانت‌ها را پشت‌سرهم داخل همان مرورگر اضافه می‌کنید (از آواتار → Add account)، و اسکریپت برای هر کدام جدا کوکی می‌گیرد و با `authuser` درست وارد pool می‌کند:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/06-add-multi-accounts.ps1 -Accounts 3
```

**قاعده‌های چند-اکانته:**
- هر اکانت در pool خودش را از «قدیمی‌ترین استفاده‌شده» انتخاب می‌کند؛ لازم نیست کاری کنید.
- هر اکانت به اولین IP‌ای که با آن کار کرده می‌چسبد (account-sticky IP) — این رفتار ضدبن است، عوضش نکنید.
- اکانتی که ۳ بار پشت‌سرهم خطای احراز هویت بدهد خودکار غیرفعال می‌شود (قرمز می‌شود در پنل)؛ کوکی تازه بدهید و enable کنید.
- اگر در یک مرورگر چند اکانت دارید و اشتراک روی اکانت دوم است، حتماً `authuser` را ست کنید وگرنه مدل Pro **بی‌سروصدا** به مدل رایگان تنزل می‌کند و «Check» هم می‌گوید لاگین سالم است!

## ۸. اتصال Claude Code و Cline

### Claude Code

Claude Code با دو متغیر محیطی تنظیم می‌شود. در PowerShell:

```powershell
$env:ANTHROPIC_BASE_URL = "http://localhost:8094"
$env:ANTHROPIC_API_KEY = "local-client-key-1"
claude
```

(در تنظیمات پروژه‌ای `.claude/settings.json` هم می‌شود این‌ها را گذاشت که بهتر است.)

اگر مدل را هم می‌خواهید ثابت کنید:

```powershell
$env:ANTHROPIC_MODEL = "gemini-4-hydrogen"
```

### Cline

در تنظیمات Cline:
- Provider: `OpenAI Compatible` (یا Anthropic اگر گزینه دارد)
- Base URL: `http://localhost:8093/v1` (مستقیم به موتور وب، بدون لایه پل)
- API Key: همان کلید `sk-gemini-...`
- Model: `gemini-4-hydrogen` یا `gemini-4-carbon`

### یک نکته مهم درباره Tool Choice

تست ما نشان داد وقتی درخواست استریم همراه ابزار باشد ولی `tool_choice` مشخص نشده باشد، مدل گاهی به‌جای صدا زدن ابزار، پاسخ متنی می‌دهد. Claude Code خودش به‌درستی `tool_choice` را می‌فرستد، پس اگر مستقیم با API کار می‌کنید و ابزار لازم دارید، حتماً `tool_choice` را ست کنید.

### اتصال به 9router (روتر مرکزی همه پرووایدرها)

اگر [9router](https://github.com/decolua/9router) دارید (روی پورت 20128)، می‌توانید پل Gemini را به‌عنوان یک پرووایدر داخلش معرفی کنید تا مدل‌های Gemini کنار بقیه مدل‌هایتان باشند و fallback خودکار داشته باشید. راهنمای کامل با تصویر گام‌به‌گام در [docs/9router-setup.md](docs/9router-setup.md) — خلاصه:

1. داشبورد `http://localhost:20128/dashboard` → Providers → **OpenAI Compatible**
2. Name: `gw2gemini`، Prefix: `gw2`، API type: `chat`، Base URL: `http://localhost:8093/v1`
3. یک Connection با کلید `sk-gemini-...` اضافه کنید
4. حالا مدل‌ها به شکل `gw2/gemini-4-hydrogen` در دسترس‌اند؛ در Claude Code:
   `$env:ANTHROPIC_BASE_URL = "http://localhost:20128"` + کلید 9router + مدل `gw2/gemini-4-hydrogen`
5. (اختیاری) یک **Combo** بسازید: اول `gw2/gemini-4-carbon`، بعد `gw2/gemini-4-hydrogen` — اگر Carbon سهمیه‌اش تمام شد، 9router خودش می‌رود سراغ بعدی.

⚠️ نکته: مسیر Antigravity OAuth (که 9router هم دارد) در موج‌های مسدودسازی ۲۰۲۶ ریسک بالاتری داشته؛ مسیر وب‌کوکیِ این پل کم‌ریسک‌تر است و کنارش در 9router خوب کار می‌کند.

## ۹. مدل‌ها — Hydrogen، Neon، Carbon و داستان Argon

گوگل در نوامبر ۲۰۲۶ منوی مدل‌های وب را عوض کرد. اگر قبلاً اسم «Gemini 4 Argon» را شنیده‌اید: **آن مدل به «4 Carbon» تغییر نام داد.** در رابط وب الان این‌ها هست:

| اسم در منوی وب | اسم API ما | چی هست | حساب لازم |
|---|---|---|---|
| Auto / Everyday help | `gemini-3.5-flash-lite` | سبک و سریع | هیچ (حتی ناشناس) |
| (مسیر پیش‌فرض) | `gemini-4-hydrogen` | مدل عمومی سری ۴ | هر اکانت لاگین‌شده |
| Deeper analysis (New) | `gemini-4-neon` | تحلیل عمیق، جانشین 3.1 Pro | اکانت Pro/Ultra |
| Code & complex work | `gemini-4-carbon` | سنگین‌ترین، جانشین 4 Argon | اکانت Pro/Ultra |

پسوند `-thinking` هم دارد: مثل `gemini-4-hydrogen-thinking` که زنجیره فکر مدل را جدا در فیلد `reasoning_content` برمی‌گرداند (برای ابزارهایی که می‌خواهند «تفکر» را نمایش دهند).

### سهمیه‌ها — مهم!

- مدل‌های Pro روی پلن ۱۹.۹۹ دلاری **سهمیه ۵ ساعته** دارند که خیلی سریع پر می‌شود (گزارش‌های کاربران: ۳ تا ۴ درخواست سنگین کافی است تا سقف بخورد).
- مدل `gemini-4-carbon` در تست ما روی یک اکانت Pro خطای «no content frame» داد — احتمالاً مربوط به سهمیه یا رفتار اکانت است. اگر این خطا را دیدید، اول `gemini-4-hydrogen` را تست کنید و بعد چند ساعت دوباره Carbon را امتحان کنید.
- پروکسی خودش بررسی سهمیه دارد: اگر سقف بگذرد، خطای واضح برمی‌گرداند نه پاسخ خاموش خراب.

## ۱۰. قوانین ایمنی ضدبن — بخوانید قبل از استفاده روزمره

> 📖 **راهنمای کامل ضدبن** با جدول کدهای خطا، لایه تراتل با Jitter و چک‌لیست راه‌اندازی امن، جدا شده به [docs/anti-ban.md](docs/anti-ban.md). یک کانفیگ سخت‌شدهٔ آماده هم برای پروکسی اعمال شده (concurrent=1، RPM=3، چت موقت، anon-first و…).

گوگل به‌طور رسمی «استفاده از وب با اسکریپت» را مجاز نمی‌داند، اما واقعیت میدانی تا نوامبر ۲۰۲۶ نشان می‌دهد اگر این قوانین را رعایت کنید، ریسک پایین می‌ماند. این‌ها را مثل قانون رانندگی در جاده کوهستانی جدی بگیرید:

1. **هرگز اکانت اصلی ندهید.** اکانت فرعی بسازید و اشتراک را همان‌جا فعال کنید.
2. **یک درخواست همزمان، نه بیشتر.** پروکسی پیش‌فرض همزمانی ۵ دارد؛ اگر solo هستید، در تنظیمات پایینش بیاورید (پنل → Settings → per_ip_concurrent = 1 یا 2).
3. **با نرخ متعادل بفرستید.** حدود ۲ تا ۳ درخواست در دقیقه برای مدل‌های Pro. پروکسی پیش‌فرض RPH=80 دارد که برای یک نفر کافی و امن است.
4. **IP خانگی، نه VPN.** گوگل IPهای دیتاسنتر و VPNهای اشتراکی را دوست ندارد. با اینترنت خانه‌تان وصل شوید.
5. **مرورگر باز نگذارید.** وقتی سرور پروکسی روشن است، تب `gemini.google.com` در مرورگرتان باز نباشد (تداخل چرخش کوکی).
6. **کوکی را فقط یک‌جا نگه دارید.** همان پروکسی که کوکی را گرفت، تنها مالکش باشد.
7. **عجله نکنید بعد از خطا.** اگر خطای سهمیه (429) گرفتید، فوری دوباره نفرستید؛ چند دقیقه صبر کنید. ارسال مکرر روی خطا = امضای ربات.

### کدهای خطا و معنی‌شان

| کد | معنی | کار |
|---|---|---|
| 429 | سهمیه تمام | ۳۰ دقیقه صبر، یا برو سراغ مدل سبک‌تر |
| 402 / 1016 | کوکی مرده یا لاگین باطل | دوباره لاگین کن و کوکی تازه بده |
| 109x | دسترسی Pro نیست | اکانت درست (پریمیوم) را در پروفایل انتخاب کن |
| 502 no content frame | جواب خالی از گوگل | چند دقیقه بعد امتحان کن؛ روی Carbon رایج است |

## ۱۱. مشکلات رایج و حلشان

**«پورت اشغال است»** — یک سرور دیگر با همان پورت روشن است. پورت را در متغیر `PORT` یا `BRIDGE_PORT` عوض کنید.

**«کوکی بعد از یک ساعت مرد»** — مشکل DBSC کروم. از فایرفاکس کوکی بگیرید.

**«Claude Code جواب نمی‌دهد / خالی برمی‌گرداند»** — چک کنید: (۱) پل 8094 روشن است؟ (۲) `ANTHROPIC_BASE_URL` درست است؟ (۳) کلید `local-client-key-1` درست است؟

## ۱۳. محدودیت‌هایی که باید بدانید

- **Tool Calling شبیه‌سازی‌شده است، نه واقعی.** پروتکل وب جمنای ابزار (tools) ندارد؛ پروکسی اسم ابزارها را داخل متن پرامپت تزریق می‌کند و از جواب مدل، بلوک ابزار را «از دل متن» بیرون می‌کشد. در اکثر مواقع درست کار می‌کند ولی ۱۰۰٪ تضمین نیست — مخصوصاً وقتی ابزارهای خیلی زیاد یا پرامپت خیلی طولانی دارید.
- **سقف طول پرامپت حدود ۱۳۰ هزار بایت است.** متن‌های خیلی طولانی باید خودتان خلاصه یا تکه‌تکه کنید (ابزارهای کدنویسی مثل Claude Code خودشان این کار را می‌کنند).
- **Deep Research و برخی قابلیت‌های پیشرفته وب پیاده نشده‌اند.**
- **تعداد توکن‌ها تخمینی است** (با tiktoken حساب می‌شود، تفاوت ±۲۰٪).
- **این پروژه زیرساخت «ناحیه خاکستری» است** — گوگل می‌تواند هر زمان قانونش را عوض کند. خودتان مسئول ریسک اکانت فرعی‌تان هستید.
