# راهنمای کامل ضدبن (Anti-Ban) — حفاظت از اکانت‌های گوگل

> هدف: استفاده طولانی‌مدت از پل بدون اینکه گوگل اکانت فرعی شما را محدود یا تعلیق کند.
> این سند ترکیبی از **مشاهدات مستند** (Issuesها و تست‌های واقعی ۲۰۲۶) و **توصیه‌های محافظه‌کارانه مهندسی** است. هرجا عدد رسمی از گوگل نیست، صریحاً گفته شده.

---

## فلسفه کلی: گوگل به دنبال چه امضایی می‌گردد؟

سیستم ضدسوءاستفاده گوگل مثل نگهبان یک ساختمان است: دنبال «رفتار عجیب» می‌گردد، نه خودِ استفاده. این رفتارهای عجیب را می‌شناسد:

1. **امضای شبکه غریبه** — برنامه‌ای که خودش را کروم جا بزند ولی دست‌دهی TLS/HTTP2 آن شبیه کروم نباشد (پروکسی ما با اثرانگشت Chrome 146 این را حل کرده).
2. **IP مشکوک** — IP دیتاسنتر، VPN اشتراکی، یا پرش مداوم IP.
3. **ریتم رباتیک** — فاصله زمانی ثابت بین درخواست‌ها، همزمانی بالا، کار ۲۴ ساعته بی‌وقفه، تکرار فوری یک پرامپت بعد از خطا.
4. **چرخش کوکی آشفته** — دو موجودیت همزمان کوکی را عوض کنند (مرورگر + پروکسی).
5. **الگوی چند-اکانته از یک IP** — ده‌ها اکانت که همه از یک IP می‌آیند = نشانه اشتراک اکانت.

هر بخش این سند یکی از این پنج جبهه را می‌بندد.

## ۱. شبکه: IP و اثرانگشت

### قاعده‌ها

| قاعده | چرا |
|---|---|
| IP خانگی/موبایل (مسکونی) استفاده کنید، نه VPN | کشف کلیدی اکوسیستم: گوگل سشن لاگین‌شده از IP دیتاسنتر را **~۲ ساعته** منقضی می‌کند؛ از IP مسکونی هفته‌ها دوام می‌آورد (منبع: تحلیل افزونه xwteam/gemini2api) |
| تعارض IPv4/IPv6 نداشته باشید | اگر کوکی با IPv4 ساخته شد و پروکسی با IPv6 می‌رود، پرش IP دیده می‌شود |
| `fallback_direct` خاموش بماند | اگر خروجی موتور قطع شود، پروکسی نباید بی‌سروصدا با IP خانه شما مستقیم برود — خطای واضح بهتر از لو رفتن IP است (این را در کانفیگ سخت‌شده فعال کرده‌ایم) |
| اثرانگشت ثابت بماند | بین chrome_146 و firefox یکی را انتخاب کنید و عوضش نکنید — جابجایی مرتب اثرانگشت خودش امضاست |

### تست واقعی ما
کوکی CDP از کروم در ۲۰ نوامبر ۲۰۲۶ دو بار ظرف ~۳۰ دقیقه مرد (DBSC + چرخش). الگوی درست: مرورگر را باز کن → کوکی تازه → مرورگر بسته → پروکسی تنها مالک. اگر باز مرد، یعنی DBSC کروم غالب شده — برو سراغ فایرفاکس.

## ۲. ریتم: نرخ و Jitter (مهم‌ترین بخش برای Claude Code)

Claude Code و Cline در حلقه‌های ایجنتی ده‌ها درخواست پشت‌سرهم می‌سازند. این «بمباران منظم» خطرناک‌ترین امضاست.

### کانفیگ سخت‌شده که روی پل اعمال کردیم

```
per_ip_concurrent = 1     ← فقط یک درخواست همزمان به گوگل
per_ip_rpm        = 3     ← حداکثر ۳ درخواست در دقیقه
per_ip_rph        = 40    ← زیر سقف تجربی ۸۰ (که در تست ریپو ۸۰-۱۸۰ بود) برای حاشیه امن
retry_attempts    = 2     ← ریت‌رای کم = امضای ربات کم
retry_delay_sec   = 8     ← فاصله ریت‌رای بلند
retry_on_timeout  = false ← تایم‌اوت = خطای واضح، نه تلاش مجدد
temporary_chat    = true  ← چت موقت: بدون ردپای تاریخچه در اکانت
anon_first        = true  ← درخواست ساده بدون مصرف کوکی پرو (کاهش ردپا)
strict_model      = true  ← تنزل خاموش ممنوع؛ خطای واضح
stream_idle_timeout_sec = 120 ← استریم مرده قطع شود
```

### لایه تراتل با Jitter (اسکریپت ۰۷)

چون پروکسی گوگل Jitter داخلی ندارد، اسکریپت [07-throttle-proxy.ps1](../scripts/07-throttle-proxy.ps1) یک لایه بین ابزار و پل اضافه می‌کند:

```
Claude Code → تراتل (:8095) → پل (:8094) → موتور (:8093) → گوگل
```

- بین هر دو درخواست، تاخیر تصادفی **۲ تا ۷ ثانیه** می‌گذارد (Jitter) — فاصله‌ها هیچ‌وقت یکنواخت نمی‌ماند.
- صف تک‌نویسنده: حتی اگر ۵ ابزار همزمان بخواهند، به‌ترتیب می‌روند.
- روی خطای 429/502 از بالادست، **cooldown سراسری ۶۰ ثانیه‌ای** می‌گذارد و به ابزار `Retry-After` می‌دهد — جلوی حلقه «خطا → تلاش فوری → خطا» را می‌گیرد که قوی‌ترین سیگنال ربات است.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/07-throttle-proxy.ps1
# بعد در Claude Code:
$env:ANTHROPIC_BASE_URL = "http://localhost:8095"   # به‌جای 8094
```

### قواعد رفتاری (خودتان رعایت کنید)

- **بعد از خطا عجله نکنید.** حداقل ۶۰ ثانیه صبر. پرامپت عین را دوبله نفرستید — کمی تغییرش دهید.
- **ساعات خواب طبیعی داشته باشید.** کار ۲۴ ساعته بی‌وقفه برای یک اکانت «شخصی» عجیب است. اگر شب‌ها پروژه سنگین دارید، اکانت‌های بیشتر (بخش ۴) بهتر از فشار روی یک اکانت است.
- **حلقه‌های ایجنتی را محدود کنید.** در Claude Code اگر می‌توانید `--max-turns` بدهید، بدهید.

## ۳. چرخش کوکی: قانون تک‌نویسنده

بزرگ‌ترین قاتل سشن، «دو نویسنده» است. پروکسی ما خودش `__Secure-1PSIDTS` را هر ~۱۰ دقیقه و SIDCC را از پاسخ‌ها تازه می‌کند. اگر همزمان مرورگر باز با تب جمنای باشد، هر دو می‌چرخانند و نسخه‌ها بلافاصله باطل می‌شوند.

| قاعده | اجرا |
|---|---|
| موقع کار پل، تب `gemini.google.com` بسته باشد | رفتاری |
| کوکی فقط از یک مسیر بیاید (مرورگر موقت یک‌بارمصرف یا فایرفاکس) | رفتاری |
| اگر کوکی تازه می‌دهید، قبلی را delete کنید نه disable | `python scripts/05-manage-accounts.py delete <id>` |
| هر اکانت به اولین IP خودش می‌چسبد (account-sticky) — دست نزنید | پیش‌فرض پروکسی |

## ۴. چند-اکانت: پخش بار بدون لو رفتن

- **هر اکانت، پروفایل کوکی مستقل خودش را دارد** — پروکسی بینشان با «کمترین استفاده اخیر» می‌چرخد؛ این خوب است چون هر اکانت الگوی استفاده «طبیعی پراکنده» پیدا می‌کند.
- **هرگز همه اکانت‌ها را همزمان سنگین نکنید.** با کانفیگ فعلی (concurrent=1) عملاً غیرممکن است.
- **اکانت مرده را فوری بگذارید کنار:** پروکسی بعد از ۳ خطای احراز هویت خودکار disable می‌کند — ادامه فشار روی اکانت مشکوک = سیگنال ربات.
- **ترتیب ساخت اکانت‌ها را پخش کنید:** همه اکانت‌ها را یک روز نسازید؛ چند روز فاصله بین ساخت اکانت‌های جدید طبیعی‌تر است.
- **SAPISID یکتا:** اسکریپت‌ها بر اساس SAPISID تکراری‌ها را تشخیص می‌دهند (در 9router هم همین است) — دو رکورد برای یک اکانت نسازید.

## ۵. کدهای خطا و واکنش درست (Circuit Breaker)

این جدول را چاپ کنید و بچسبانید کنار مانیتور 😄

| خطا | معنی | واکنش پروکسی (خودکار) | واکنش شما |
|---|---|---|---|
| `429` / پیام سهمیه | سهمیه ۵ ساعته تمام | cooldown مدل، بدون ریت‌رای فوری | ۳۰+ دقیقه صبر یا مدل سبک‌تر یا اکانت بعد |
| `402` / `1016` / 401/403 | کوکی مرده | قرنطینه اکانت، بدون retry | کوکی تازه بگیرید (مرورگر → اسکریپت 03) |
| `109x` | دسترسی Pro نیست | strict_model خطا می‌دهد نه تنزل | authuser اکانت را چک کنید (اشتراک روی کدام /u/n است؟) |
| `502 no content frame` | جواب خالی (اکثراً Carbon) | ۲ ریت‌رای با فاصله ۸ ثانیه | چند دقیقه بعد؛ یا موقتاً Hydrogen |
| `card_content` در استریم | کارت خطای موقت گوگل | فیلتر و بستن تمیز استریم | خودکار حل می‌شود |
| پرش به مدل رایگان | تنزل خاموش | strict_model جلویش را می‌گیرد (429 برمی‌گرداند) | کوکی/اشتراک اکانت را بررسی کنید |

## ۶. ریسک‌های پذیرفته‌شده (صراحت)

- **هیچ پروژه‌ای ادعای «ضدبن تضمینی» ندارد** — حتی README های gemini-stealth-bridge صریحاً می‌گویند «محافظت تضمین نمی‌شود».
- مسیر **Antigravity OAuth** (که 9router هم دارد) در موج‌های مارس و ۱۴ نوامبر ۲۰۲۶ مستقیماً هدف بن بوده؛ مسیر وب‌کوکی تا امروز موج بن مستند «مخصوص وب» نداشته ولی پیشینه بن CLI/Antigravity نشان می‌دهد الگوی اجرای قانون وجود دارد.
- در بدترین حالت محتمل: محدودیت موقت ۲۴ ساعته سهمیه، کپچا، یا تعلیق ۷-۳۰ روزه سرویس‌های AI اکانت فرعی. به‌خاطر همین اکانت فرعی می‌خواهیم.
- **Workspace آگاه باشید:** مدل وب به Gmail/Drive اکانت دسترسی دارد. اگر اکانت فرعی داده شخصی دارد، افزونه‌های Workspace جمنای را در تنظیمات وب خاموش کنید — هم ریسک Prompt Injection می‌بندد هم ردپا کم می‌کند.

```
□ تب gemini.google.com در مرورگر روزمره بسته است
□ python scripts/04-test-api.py هر سه تست را پاس کرده
□ python scripts/05-manage-accounts.py check همه را «لاگین معتبر» گفته
```
