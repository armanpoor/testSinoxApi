# اتصال پل Gemini به 9router

> این راهنما فرض می‌کند پل شما (بخش README اصلی) روی پورت **8093** (موتور وب) و **8094** (پل Anthropic) فعال است و 9router هم روی **20128** در حال اجراست.

## ایده کلی

9router یک «روتر مرکزی» است: همه ابزارهای شما (Claude Code، Cline، OpenCode، Cursor و…) به یک آدرس وصل می‌شوند و 9router تصمیم می‌گیرد کدام مدل/پرووایدر جواب بدهد. ما پل Gemini را به‌عنوان یک **پرووایدر OpenAI-Compatible** به 9router معرفی می‌کنیم تا مدل‌های Gemini کنار مدل‌های دیگرتان در یک لیست باشند — با fallback خودکار (اگر سهمیه Gemini تمام شد، برو سراغ مدل بعدی).

```
Claude Code / Cline / هر ابزار
        │
        ▼
9router (:20128)  ← مدیریت همه پرووایدرها
        │
        ├─► gw2gemini (پرووایدر سفارشی) → پل :8094 → موتور :8093 → gemini.google.com
        ├─► سایر پرووایدرها (Claude، Codex، ...)
        ▼
```

## گام ۱: داشبورد 9router را باز کنید

`http://localhost:20128/dashboard` (رمز پیش‌فرض `123456` — اگر عوضش نکرده‌اید همین را بزنید؛ بهتر است عوضش کنید).

## گام ۲: پرووایدر جدید بسازید

در داشبورد → **Providers** → **Add Provider** → نوع **OpenAI Compatible**:

| فیلد | مقدار | توضیح |
|---|---|---|
| Name | `gw2gemini` | هر اسمی؛ این فقط نمایشی است |
| Prefix | `gw2` | پیشوند مدل‌ها: `gw2/gemini-4-hydrogen` |
| API type | `chat` | — |
| Base URL | `http://localhost:8093/v1` | ⚠️ **مستقیم موتور وب، نه پل 8094** (چون 9router خودش فرمت Anthropic را هم می‌فهمد و ترجمه دوباره لازم نیست) |

بعد روی پرووایدر **Connection** اضافه کنید:
- API Key: همان کلید `sk-gemini-...` موتور وب (از پنل ادمین 8093)

## گام ۳: مدل‌ها را چک کنید

9router خودش `/v1/models` پرووایدر را می‌خواند. در PowerShell:

```powershell
curl.exe -s http://localhost:20128/v1/models | findstr "gw2"
```

باید مدل‌های `gw2/gemini-4-hydrogen`، `gw2/gemini-4-neon`، `gw2/gemini-4-carbon` و… را ببینید.

## گام ۴: یک API Key از 9router بسازید

در داشبورد → **API Keys** → کلید جدید بسازید. این کلیدِ خود 9router است و به برنامه‌ها می‌دهید.

## گام ۵: ابزارها را به 9router وصل کنید (نه مستقیم به پل)

مثال Claude Code:

```powershell
$env:ANTHROPIC_BASE_URL = "http://localhost:20128"
$env:ANTHROPIC_API_KEY = "کلید-9router-شما"
claude --model gw2/gemini-4-hydrogen
```

مثال Cline:

```
Provider: OpenAI Compatible
Base URL: http://localhost:20128/v1
API Key: کلید-9router-شما
Model: gw2/gemini-4-hydrogen
```

## گام ۶ (اختیاری ولی توصیه‌شده): Combo با fallback

در داشبورد → **Combos** یک ترکیب بسازید، مثلا اسمش را `my-coder` بگذارید و ترتیب این‌طور باشد:

1. `gw2/gemini-4-carbon` (وقتی جواب داد، بهترین کیفیت)
2. `gw2/gemini-4-hydrogen` (سریع‌تر و همیشه در دسترس)
3. مدل هر پرووایدر دیگری که دارید

بعد در Claude Code فقط `--model my-coder` می‌زنید؛ 9router خودش اگر Carbon خطا داد، بدون دیده‌شدن شما به Hydrogen می‌رود.

## نکات مهم

- **چرا Base URL پل (8094) را ندادیم؟** 9router هم فرمت OpenAI و هم Anthropic را بلد است. موتور وب (8093) فرمت OpenAI دارد و کافی است. دادن پل هم اشکالی ندارد ولی یک ترجمه اضافه در مسیر می‌گذارد.
- **سهمیه‌ها جدا جمع نمی‌شوند.** چند اکانت در Cookie Pool دارند خودشان بینشان می‌چرخند؛ 9router از بیرون فقط یک پرووایدر می‌بیند. اگر می‌خواهید هر اکانت را جدا در 9router ببینید (مثلاً برای کنترل دستی)، به‌جای یک پرووایدر، چند پرووایدر با Base URL های مختلف بسازید — ولی پروکسی گوگل را باید چندبار با پورت‌های متفاوت بالا بیاورید (پورت 8095، 8096 و…؛ هر کدام DB خودش).
- **قبلاً 9router با Antigravity OAuth تست کرده‌اید؟** مسیر Antigravity ریسک بن بالاتری دارد (موج‌های مسدودسازی مارس و نوامبر ۲۰۲۶). مسیر وب‌کوکی این پروژه کم‌ریسک‌تر است ولی هر دو را می‌توانید همزمان در 9router داشته باشید.
- **مراقب حلقه باشید:** 9router را به خودش (Base URL = 20128) معرفی نکنید!

## عیب‌یابی سریع

| مشکل | حل |
|---|---|
| مدل‌های `gw2/...` در لیست نیستند | موتور 8093 روشن است؟ در داشبورد روی Refresh/Retry پرووایدر بزنید |
| خطای 401 از پرووایدر | کلید `sk-gemini-...` اشتباه است؛ از پنل ادمین دوباره بردارید |
| «prefix not used» (ایشو شناخته‌شده 9router#5763) | مدل را با اسم کامل `gw2/...` صدا بزنید |
| fallback کار نمی‌کند | در Combo ترتیب مدل‌ها را چک کنید؛ فقط مدل‌های سلامِ پرووایدر وارد fallback می‌شوند |
